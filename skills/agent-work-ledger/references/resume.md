# Continue or resume executable work

Use for active executable work with a canonical execution surface. Apply shared rules from `AGENTS.md`; if PR feedback is active work, use `feedback`.

If the canonical Issue is still exploratory and the requested work is investigation, direction-setting, or decomposition rather than delivery against an accepted contract, switch to `shape.md` before continuing. Do not infer that an Issue is executable merely because it records a next step.

1. Verify the recorded next action against the executable task definition and smallest relevant evidence.
2. If standalone work now needs an independent lifecycle, promote it when authorized; otherwise record that promotion as the blocker or next action.
3. Execute the smallest concrete next action; replace superseded `Current State` and record only validation actually performed.
4. Switch to `shape` when new evidence explicitly reopens the underlying direction, to `blocker-handoff` when blocked or handed off, to `feedback` when PR feedback becomes active work, or to `review` only when required or requested.
5. If a required transition lacks authority, leave it as the exact next action.

If implementation evidence materially invalidates an accepted initiative direction, stop treating that direction as silently mutable execution context. Record the contradiction on the canonical initiative surface and switch to shaping when authorized to revisit it.

## Done when

The requested executable increment is complete and durable state matches evidence, or the next required lifecycle path or authorized transition is explicit.
