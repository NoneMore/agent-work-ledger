# Continue or resume executable work

Use this path for active executable work with a canonical execution surface. Apply the recovery budget from `AGENTS.md`.

If the canonical Issue is still exploratory and the requested work is investigation, direction-setting, or decomposition rather than delivery against an accepted contract, switch to `shape.md` before continuing. Do not infer that an Issue is executable merely because it records a next step.

1. Verify the recorded next action still advances the current executable task definition and matches the smallest relevant repository evidence.
2. If standalone work now needs an independent lifecycle, promote it when authorized; otherwise record that promotion as the blocker or next action.
3. Continue from the smallest concrete next action.
4. Replace superseded `Current State` rather than appending progress history, and record only validation actually performed.
5. Switch lifecycle paths if the work becomes blocked, is being handed off, newly discovered evidence reopens the underlying direction, is ready for review, or the user asks for review.

If implementation evidence materially invalidates an accepted initiative direction, stop treating that direction as silently mutable execution context. Record the contradiction on the canonical initiative surface and switch to shaping when authorized to revisit it.

## Done when

The requested executable increment is complete and durable state matches evidence, or another lifecycle path is required.
